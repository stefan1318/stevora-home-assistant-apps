# [STE-05] STEVORA Universal Integration 0.2.0-rc.1 — финални тестове

**Статус:** кандидат за финални тестове, **НЕ е производствена версия**.
**Източник:** GitHub PR #6 към PR #5; използва се само проверената компилация от успешен CI run.
**Обхват:** Home Assistant Universal Integration (Core + Home Panel). Не съдържа самостоятелен Home Hub, Hey Stevora voice engine, Memory Sync, Android APK или iOS IPA.

## Установени и коригирани дефекти

- `auto_discovery=false` преди не влияеше върху откриването. Сега изключва автоматичните устройства, но запазва ръчно включените, избраните light/climate и персонализираните от администратора.
- HA конфигурационните/диагностичните entities се пропускат по подразбиране; администраторът може изрично да ги включи. Disabled и hidden остават забранени.
- Подсветките се разпознават по оригинално HA име, а не само по променяемия STEVORA alias. Не се предлагат управляващи контроли за тях.
- Manifest revision включва данните за устройства, не само mapping на идентификаторите.
- Профил без `controls` пази стандартните позволени контроли. Изрично `controls: []` или layout `info` показва само информация.
- BG/EN преводът поддържа разпознати съставни имена. Неизвестните собствени имена не се превеждат автоматично.
- Home Panel изчиства стария manifest при смяна на HA connection/user и отказва несъответстващи revisions.
- Редакция в администраторски полета вече не се изтрива от всеки HA state update.

## Създаване и проверка на ZIP

1. Отворете [PR #6](https://github.com/stefan1318/stevora-home-assistant-apps/pull/6) > **Checks**, след това последната успешна **STEVORA integration checks** компилация.
2. В **Artifacts** изтеглете `STEVORA-Universal-Integration-0.2.0-rc.1`.
3. Разархивирайте GitHub artifact ZIP. Вътре трябва да има `stevora-universal-integration-0.2.0-rc.1.zip` и `SHA256SUMS.txt`.
4. Проверете SHA256 на вътрешния ZIP с `SHA256SUMS.txt`. Неговото съдържание трябва да е `custom_components/stevora/` (не целият repo).
5. Отбележете commit SHA на успешния run. Не замествайте ZIP с архив от произволен клон.

**Никога не инсталирайте едновременно `stevora_manifest` и `stevora`.** И двата регистрират `stevora/manifest`.

## Инсталиране само на независим тестов Home Assistant

1. Направете пълен backup в **Settings > System > Backups** на тестовата инсталация.
2. Уверете се, че това **не е Home Assistant Dunav** и няма действащ legacy `stevora_manifest` компонент.
3. На тестовия HA копирайте файловете от вътрешния ZIP под `/config/custom_components/stevora/`. При съществуваща тестова версия първо копирайте старата папка отделно за rollback.
4. Проверете наличието на `/config/custom_components/stevora/manifest.json` и `frontend/stevora-panel.js`.
5. Рестартирайте HA, след това добавете **STEVORA Ecosystem** през **Settings > Devices & services**, ако не е конфигурирана.
6. Отворете `/stevora`, после инспектирайте **Settings > System > Logs** за STEVORA грешки.

## Изходни критерии

- **CI PASS**: Python contract tests, JS tests, JSON schema smoke checks и ZIP SHA256.
- **Independent HA PASS**: всички A/B/C проверки с логове и screenshot-и без чувствителни данни.
- **Mobile PASS**: D03/D04 на физически устройства, за предпочитане върху две отделни HA инсталации.
- **Release approval**: изрично одобрение след backup/rollback rehearsal; чак тогава merge и производствено внедряване.

`rc.1` е кандидат за приемане, **не удостоверение за съвместимост с реален HA Core**. Home Hub, Hey Stevora и Memory Sync остават отделни продукти с отделни приемателни тестове.
